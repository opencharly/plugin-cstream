# 2026.242.1148 — feat: the cstream check verb (status + login)

## Summary

WP8: the `cstream` check verb — the probes that can only be answered from the **stream** side of a
cstream deployment. Out-of-process over go-plugin gRPC, like every other live probe verb.

**Two methods, and every one of them is exercised live.**

| method | why it exists | why not something that already exists |
|---|---|---|
| `status` | the **gateway's own readiness view** — ready only when a DRM render node exists **and** the compositor has published a socket | strictly more than `http:` against a port: a gateway that is up with nothing to stream reports `ready:false` |
| `login` | one PAM authentication through the **real session leader** | nothing else drives the leader; `expect: accept\|reject` makes the refusing case assertable, which is what stops a stack that accepts anything from passing |

## What is deliberately NOT here

**`frame`** — a frame pulled back through the negotiated WebRTC track. It is the method this verb
ultimately exists for, because `wl: screenshot` reads the **compositor** and so structurally cannot
fail on an encoding or transport defect, whereas `frame` has all three in its failure path.

Its gate cannot pass yet: signalling negotiates a session end-to-end — producer registers, consumer
registers as `[Consumer]`, `startSession` sent, session started — and **no media follows**. That is
tracked as WP3d and is *not* the empty-compositor problem, which the working frame tap rules out.
Offering a method whose gate cannot pass reads as coverage while providing none, so the schema
records the intent in place of the method.

The architecture also lists `session-list`, `stats`, `volume`, `clipboard`, `idle`, `input` and
`logout`. None is offered: the streamer has no control surface behind them.

## A limitation recorded where someone will hit it

The `password` field is **not private**. The venue executor exposes only
`VenueCapture(ctx, cmd string)` — there is no stdin channel to an out-of-process verb — so the value
reaches the venue inside a command string and lands in `sh -c` argv, world-readable through
`/proc/<pid>/cmdline`. `cstream: login` is therefore for **fixture** credentials. The schema and the
method both say so. The production path does not have this property and must not grow it: the
broker execs the leader over a socketpair and the leader reads the credential from **stdin**.

## How tested

**1. Package gates:** `gofmt -l` silent, `go vet ./...` silent, `go build ./...` clean.

**1b. The generated params are ASSERTED against the CUE source, not assumed to match:**

```
CUE fields: ['expect', 'method', 'password', 'user']
generated  : ['expect', 'method', 'password', 'user']
MATCH
```

This check exists because the first revision drifted: `cue_types_gen.go` still declared
`Artifact`/`ArtifactMinBytes` after `frame` was withdrawn. The edit that should have removed them
silently matched nothing — `gofmt` had realigned the struct tags — and I did not verify it landed.

**2. Every offered method executed live, on a green bed:**

```
$ charly check run check-cstream-pod
charly check run check-cstream-pod: PASS (steps=13)

live checks: 50 PASS / 0 FAIL
summed over every step:  errors=0  warnings=0  allowlisted=30
```

```
PASS  the cstream verb dispatches through the provider registry and reports the gateway's readiness  [cstream-verb-status]
      → {"service":"cstream-gateway", ...}
PASS  the cstream verb ACCEPTS a correct credential through the real session leader  [cstream-verb-login-accept]
      → LOGIN-ACCEPTED user=user
PASS  the cstream verb REFUSES a wrong credential against the same stack  [cstream-verb-login-reject]
      → LOGIN-REJECTED user=user
```

**3. The login gate discriminates.** Both legs run against the **same account on the same stack**,
so neither can pass vacuously: a stack that accepted anything fails the reject leg, and a broken PAM
path fails the accept leg. A probe that only ever checked the correct password would pass just as
happily against a stack with no authentication at all.

**4. `primary:` is load-bearing and is exercised.** The scalar shorthand (`cstream: status`) works
only because the candy manifest declares `primary: {cstream: method}` — charly's pre-parse reads it
off the raw YAML. The bed uses the scalar form for `status` and the map form for `login`, so both
authoring shapes are covered. A metalayer bed that did **not** have this candy in scan range failed
with `plugin verb "cstream" takes a MAP input`, which is the same fact from the other side.
