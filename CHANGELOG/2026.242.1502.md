# 2026.242.1502 — feat: offer cstream: frame, now that it can actually be gated

## Summary

Offers `cstream: frame` — a frame pulled back **through the negotiated WebRTC track** — now that it
can actually be gated.

This is the method the verb exists for. Everything else in this stack that looks at pixels looks at
the **wrong end** of the pipeline:

| what | reads | fails on an encode/transport defect? |
|---|---|---|
| `wl: screenshot` | the compositor | **no** — never touches the encoder or the wire |
| `stream-probe` | the producer's own pipeline tap | **no** — proves frames are produced, not that any leave the process |
| `cstream: frame` | what a **real consumer decodes** | **yes** |

**Why it was withheld, and why that is over.** The schema said so in as many words: *"NOT offered
yet: signalling negotiates a session end-to-end and no media follows (WP3d, cause not yet
understood). Offering a method whose gate cannot pass would read as coverage while providing none."*

That cause is now root-caused and fixed. `gst-plugins-bad` was missing, so `webrtcbin` did not
exist and `webrtcsink` failed to build its session pipeline with a **WARN** — sessions negotiated,
no media followed, no ICE or DTLS error surfaced, and every producer-side check passed
(`opencharly/pod-cstream#7`). The condition the schema set for shipping this method is met, so the
rationale comment is replaced with what the method *is*.

That is **6 files**: five under `candy/plugin-cstream/` plus the new test file.

`frameMethod` runs `/usr/local/bin/cstream-frame-probe` in the venue, pulls the file back over the
executor's reverse channel (`GetFile`), and writes it to `in.Artifact` — a **host** path — *before*
the provider's artifact validators run. That ordering is what lets `artifact_min_bytes` /
`artifact_not_uniform` gate the bytes a consumer actually received. It refuses to run without an
`artifact:`, because a frame method that reports success for a stream which sent nothing is exactly
the failure it exists to catch.

## ⚠️ On `params/cue_types_gen.go` changing more than the added field

The diff there is **+92/−6**, not four lines, and that deserves an explanation rather than a reviewer
discovering it.

The file is generated (`Code generated … DO NOT EDIT`) and was regenerated through the documented
pipeline — `schemagen -mode=concat` → `cue exp gengotypes` (v0.16.1, the pinned version) →
`schemagen -mode=retag` → `gofmt`. It was **not** hand-edited.

The committed file predates the *"principled yaml-tag retag transform"* the schema-change recipe
describes, so it carries `json:` tags only and a condensed banner. **Verified by control:**
regenerating from the **unchanged** schema does not reproduce the committed file either —

```
committed != fresh-from-unchanged-schema   (so the file was already stale before this PR)
```

— which means the extra churn is the generator catching up, not drift introduced here. Hand-matching
the output back to the old shape would have violated SDD's "never hand-edit the generated files".

`artifact_not_uniform` is the assertion that matters: it passes only because a **decoded, non-uniform
frame** reached a host path, so a stream that negotiated and then sent black or a placeholder would
fail here. That is the gate this plan withheld the method for.

### 1b. The gate caught a real defect in this PR before it shipped

The first run of exactly this step **failed**:

```
FAIL  [cstream-frame-through-webrtc]
      plugin verb:cstream: plugin_input fails #CstreamInput:
      #CstreamInput.artifact_min_bytes: field not allowed (and 1 more errors)

61 steps: 56 passed, 1 failed, 4 skipped     <- only this check; everything else green
```

`artifact_min_bytes` / `artifact_min_dimensions` / `artifact_not_uniform` are **not** general `#Op`
modifiers — they left core `#Op` in the schema-compaction cutover, so every verb that writes an
artifact declares its own (`plugin-wl` carries the same four). This schema declared only `artifact`.

`go build`, `go vet` and `go test` all passed on that broken tree: the Go side compiles fine and the
**host** rejects the step before the provider is reached. Only authoring the verb in a live bed
surfaced it. The four validators are now declared, and the CUE comment records how the omission was
found so the next verb author does not repeat it.

### 3. The drift tests discriminate

Three tests guard the CUE↔Go contract, which matters here specifically because re-adding a method
touches the enum, the generated struct **and** the dispatch switch — and a method present in one but
missing from another either dies at runtime on the default arm or is rejected by the host before the
provider is reached.

Proven to fail on a real divergence rather than merely passing:

```
$ sed -i 's#"status" | "login" | "frame"#"status" | "login"#' schema/cstream.cue
$ go test ./...
--- FAIL: TestSchemaOffersEveryDispatchedMethod
    dispatch serves method "frame" but the CUE enum does not offer it —
    the host rejects the step before the provider is reached
FAIL
```

`TestGeneratedParamsMatchSchemaFields` covers the other direction: `frame` is useless without
`artifact`, since the provider gates validation on `in.Artifact != ""`, so a struct missing that
field would silently downgrade the check to "did not error".
