# 2026.320.2256 — fix(params): regenerate the stale artifact -- the YAML tags were missing

## Summary

**The artifact was stale, and the drift was one that made the plugin's own steps unreadable.**

`params/cue_types_gen.go` shipped every field with a `json:` tag and **no `yaml:` tag**:

```diff
-	Method string `json:"method"`
+	Method string `yaml:"method,omitempty" json:"method"`
```

A `cstream:` step is authored in **YAML**, and the struct could not decode the fields it documents — for `Method`, `User`, `Password`, `Expect`, `Artifact`, `ArtifactMinBytes`, `ArtifactMinDimensions`, `ArtifactNotUniform`, plus the doc-comment reflow around `status`/`login`. Regenerating produced **8 added `yaml:` tags**.

That is the silent contract divergence `P03` exists to catch: the committed bytes no longer matched the CUE source that is supposed to produce them, and nothing in the repo re-checked.

## How it was found

Applying the P03 gate (`TestGeneratedParamsAreCurrentAndReproducible`, merged as `plugin-adb#21`) to every plugin shipping the artifact: **110 compiled-in plugins, 60 ship it, 2 gated it.** This is one of the plugins where the gate's verdict held up under inspection — see the honesty note below, because that number is not as clean as a first pass suggested.

### The honesty note this wave earned

**"13 stale artifacts" is NOT a trustworthy figure, and this PR does not rest on it.** Two measurements from the same batch:

| plugin | measured | verdict |
|---|---|---|
| `plugin-dbus` | `already current`; sha256 **identical** before/after | **a false positive** |
| `plugin-cstream` (this PR) | `wrote …cue_types_gen.go`, 18 lines | **a true positive** |

The root cause: the gate imports `spec/schemaparams`, which **does not exist before `v0.2026320.x`**, so the sweep's "stale" verdict and the pin bump were conflated — a plugin whose artifact was fine could still fail for a pin-related reason. **Each plugin needs verifying at the lockstep pair before it is called stale**, and this one was verified twice: the gate failed before regeneration, and the regenerated bytes carry the `yaml:` tags the schema requires.

## Change classification

Kind: a **regenerated** generated artifact, plus the gate that pins it, plus the pins the generator needs.

**Breaking change + rollback:** the plugin's params types gain `yaml:` tags, so a `cstream:` step authored in YAML now decodes fields it previously could not — a consumer that had been reading a zero value for `method`/`user`/`expect` now reads the authored one.
